# S7b passes every criterion it registered, and the only gain it is allowed to count is one bench row

2026-10-29. S7 died on 2026-10-28 because halving `primer_mid_penalty` moved the
positives and the within-family negatives together: it fixed false negatives and newly
banded HPV55 and HPV44. The finding that outlived it was that no *position-blind* value
of that penalty separates the two, and that identity might
(`docs/journal/2026-10-28-s7-mid-window-killed.md`). S7b is that candidate, priced here.

`scoring.mispair_window` (shipped 2026-10-28, null = `primer_3prime_window`) is how far
from the 3' end `mispair_penalty` acts; the scope used to be a constant in
`score_primer`. S7b sets it to 10, which reaches the mid window and nothing beyond it.
The table it widens holds the one entry the project has ever shipped: G:T and T:G at 0.0.

## What it does

A replay over `results/2026-10-27/calls.tsv.gz` moves **31,237 calls** — 22,600
`reduced -> detect` and 8,637 `fail -> reduced`, every one a loosening, as predicted.
S7 moved 45,797, so widening identity costs about two thirds of what discounting
position cost, which says most mid-window mismatches are not wobbles.

**The S0 control had to be re-run first.** The control sitting in the scratchpad was from
2026-10-27 and carried `mispair_penalty: {}` and `by_chemistry: {}` — it predates M1 and
S3b. Scored against it, S7b "fixed" 12 bench rows and read 93.3% against 86.6%. Almost
all of that was M1's and S3b's. The current control reproduces the shipped calls table
exactly (`--expect-identical`, 0 moved) and the honest comparison is:

| | shipped | S7b |
|---|---|---|
| bench rows right | 166 of 179 (92.7%) | **167 of 179 (93.3%)** |
| false negatives | 12 | **11** |
| false positives | 1 (HPV71) | **1 (HPV71)** |
| bench predictions moved | — | **1** |

The one row is PPRV Nigeria75/1 on the Barrett morbillivirus panel: a band in the paper,
`fail` at penalty 4.0 under the shipped rule, `reduced` at 3.0 under S7b. Its two
3'-window wobbles (fwd2 G:T, rev3 G:T) were already free; what moved is one mid-window
wobble worth exactly 1.0. **No within-family negative gained a band** — HPV55 and HPV44,
the two rows that killed S7, stay `fail`.

Tier-2 on the development set is **identical case for case**: 6/11 documented failures
caught, PPV 4/10, 4/32 false alarms, 2/6 partial gaps, same credits to the same statuses.

So all three kill criteria are passed, including the third, which was the interesting
one: the positives and the within-family negatives **separated** this time. Position could
not do that; identity can.

## And the part that has to be read carefully

The report says more than the panels do. Rendered off the replayed calls, **7 assays
change status, all of them a flag falling**:

| | |
|---|---|
| `watch -> stable` | Entamoeba_18S_small_subunit_SSU, RANAVIRUS_dsDNA_Major_capsid_protein_MCP_Johnson_2008 |
| `low coverage -> stable` | ADENOVIRUS_dsDNA_Polymerase_Primate_speci (+ `_Casas_2005`), Morbillivirus_including_CDV_P_gene (+ `_Barrett_2003`) |
| `declining -> stable` | **MONKEYPOX_dsDNA_G2R_generic_TaqMan_Li_2010** |

That last row is held-out set 2's one false alarm. Mills 2022 validated the G2R generic
assay on 2022 outbreak clinical specimens; the shipped config calls it `declining`; S7b
calls it `stable`. The trace that opened this whole line of work was that same assay's
G:T wobble at reverse position 8 (`docs/journal/2026-10-28-g2r-false-alarm-traced.md`),
so this is the candidate doing exactly what it was built to do, on the row that pointed
at it.

**It cannot be counted as evidence, and it is not why S7b passed.** The held-out row said
where to look; the pricing above is on the development set and the bench panels, which
are the only data a threshold may be fitted to here. Recording the move is required — the
file is a further bit spent either way — but a candidate justified by a held-out row is a
candidate fitted to a held-out row, which is the one thing
`docs/validation-cases-heldout-2.tsv` exists to prevent.

Which leaves the decision honestly stated rather than dressed up:

- On data this project is **allowed** to spend, S7b is **one bench row better and
  tier-2-neutral**. That is a thin result for a change that clears 7 flags.
- On data it is **not** allowed to spend, it fixes the one false alarm in three held-out
  rows, by the exact mechanism predicted before the run.
- 5 distinct assays (7 rows, two of them round-1/round-2 pairs) stop being flagged, and
  for 6 of the 7 there is **no ground truth either way**. If they are real coverage
  problems, S7b hides five of them; if they are false alarms like G2R, it fixes five.

`mispair_window` therefore stays **null**. S7b is registered, priced, passing, and
**awaiting a maintainer's call**, which is the honest status for a candidate whose
strongest number is one the rules forbid using. A replay prices and does not prove, so
shipping it means a confirming rescreen as well.

## What would settle it

Not another threshold run. The 6 flags with no ground truth are the question, and the
answer is cases: `scripts/check_candidate_identity.py` over the new `use`-family
retrospective queue returned **13 CONFIRMED (paper, assay) pairs over 7 papers** the same
day (up from 2 in the whole project before), and two of them are ADENOVIRUS hexon and
pan-herpes — adjacent to the assays S7b unflags. Reading those is worth more than a
third value of a mid-window knob.
