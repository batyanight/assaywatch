## Where the project is

The pipeline retrieves GenBank records per assay target, screens each record
against the assay's oligos, and reports which assays have drifted. That part
works and is not what needs attention.

**The open problem is the estimand.** A per-assay verdict is computed from the
*pooled* detected share across all records for that target. Pooling hides
lineage-specific failure: an assay that detects 90% of records overall can
detect 0% of a particular lineage, and the pooled number will not show it.
The validation set makes this concrete — it catches 1 of 12 known failures.

The fix, designed in `docs/journal/2026-10-17-estimand-plan.md`, is to condition on
lineage: group each assay's records by NCBI taxid, compute the share per
lineage, and let the worst assessable lineage drive the verdict.

## Traps worth knowing

- **The screen cache.** Editing any of `chance, degeneracy, fasta, iupac, loci,
  match, schema, score, screen, thermo, validate, windows` invalidates all
  cached screens and forces a full rescreen (~1.5 h). Everything done today
  stayed outside that set deliberately.
- **A plain `snakemake` run rescreens nothing** unless a signature, param or
  input changed. With only new calls to collect it schedules `report`,
  `site_drift`, `all` and finishes in under a minute. Check `snakemake -n` job
  stats before claiming a run will take hours — I got this wrong today.
- **To test a screen without touching the cache**, run the module directly with
  `--only <assay_id>` and `-o` into a scratch path, then diff against
  `results/screened/<taxid>/<group>/<date>.tsv`. Nothing is invalidated.
- **Accession keys.** The calls table identifies records by `record_id` and
  carries *versioned* accessions (`AB027157.1`); metadata and the taxid sidecar
  are keyed *unversioned*. Join on the base accession. Three bugs today came
  from this, and all three failed silently as "unresolved" rather than erroring
  — hence the `MIN_RESOLVED_SHARE` guard in `lineage_report.py`, which aborts
  below 50% resolved instead of writing a meaningless report.
- **Archive layout** is `data/retrieved/<taxid>/<group>/<date>.meta.tsv.gz`, so
  `rglob`, not `glob`.
- **Credentials** are in `.secrets/` and read by `assaywatch.credentials`; the
  NCBI key is picked up automatically and verified working
  (`check_ncbi_key()` -> HTTP 200). E-utilities also wants a contact email,
  passed as `--email`.
- **New Snakefile rules** that run `python -m assaywatch.<module>` must be added
  to the `hashed` dict in `tests/test_triggers.py` or exempted with a reason.
