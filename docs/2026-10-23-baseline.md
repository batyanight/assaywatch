# Frozen baseline for the plan of attack (2026-10-23)

Every change in the plan of attack is measured against this. It exists because
`docs/2026-10-22-M1-tier2.md` records losing a table mid-experiment — "which
overwrote the global-value table from the 00:30 run; its confusion matrix above is all
that survives of it" — and that must not happen again. Freeze first, change second.

## What is frozen

`results/2026-10-22/` copied to **`results/baseline-2026-10-22/`** (17 MB, gitignored
like every other run). Its sidecar identifies it:

|---|---|

| collected | 2026-10-22T16:17:50-04:00 |
| screening code-and-config sha1 | `be2e863ca5bfacb5ad2b490a599b4709f1ca5258` |
| git commit **of the screen** | `0f49325` |
| git HEAD when frozen | `ed3ade5` — **5 commits later** |

That last row is the sidecar doing its job. The table was screened five commits before
the tree it is being read from, which is exactly the mosaic problem
`README.md` describes the sidecar as existing to make visible. None of the five commits
touches the screen signature (they are RESUME-HERE edits and registry metadata), so the
table is still valid — but the gap is recorded rather than assumed away.

## Report statuses at the freeze

204 assays reported: **38 declining, 41 low coverage, 14 watch, 34 insufficient data,
14 no recent data, 63 stable.** So 93 of 204 (**46%**) carry a flag.

Of the 38 `declining`: 18 are lineage overrides, 12 are degeneracy-**severe** and 6
degeneracy-high, 6 carry a note that says "a coverage gap, not drift", and 24 carry at
least one provenance-doubt flag in `needs_review`.

The tool emits **9 `declining` calls** across the 49 cases. **2 are true failures.**

### What the 5 `fails` catches actually are

Only **2 of the 5** are the drift flag. The mechanism rule at
`scripts/retrospective.py:101` credits `low coverage` for a `fails` case whose recorded
mechanism is `coverage`, which is defensible — but it means three of the five catches
come from a status that carries almost no information:

| `declining` | `Paramyxovirinae_..._Tong_2008_round1` | 2019-02-01 |

has one ground-truth event. What is validated here is coverage auditing against current

## How small this instrument is

Because every later wave will be tempted to read a one- or two-case delta as a result,
the uncertainty on these point estimates is recorded here once, with a Jeffreys
prior Beta(0.5, 0.5):

| quantity | point | 95% credible interval |
|---|---:|---|
| `fails` caught, 5/11 | 45.5% | **(20.0%, 73.0%)** |
| `fails` caught among decided, 5/8 | 62.5% | (29.5%, 88.1%) |
| PPV of `declining`, 2/9 | 22.2% | **(4.9%, 54.4%)** |

Collapsing the 11 `fails` rows to distinct source papers leaves roughly **7 independent
failure events** (`docs/validation-cases.tsv` flags the non-independence itself: Bd x2
papers, Kolesnik 2019 x2 rows, Hoon-Hanks 2019 x2, Lotta 2019 x2, plus the four gB rows
from one paper). Seven events, and at least seven `config.yaml` settings have been
accepted or rejected on their effect on this matrix.

**So a "-1 FP, 0 TP" improvement is inside the noise**, and the interval above is the
reason to say so numerically rather than rhetorically. This is the whole argument for
wave 4.

## Reproducing this file

Nothing above was transcribed by hand. The matrix, the PPV, the false-alarm and miss
lists come from parsing the `retrospective.py` output; the call breakdown from one pass
over `calls.tsv.gz`; the registry counts from `python -m assaywatch.validate registry`;
the credible intervals from `scipy.stats.beta.ppf`. Re-derive with the command above
plus:

```bash
gzcat results/baseline-2026-10-22/calls.tsv.gz |
  awk -F'\t' 'NR>1{c[$3]++; if($3=="no_amplicon") e[$11]++}
              END{for(k in c) print k, c[k]; for(k in e) print "  "k, e[k]}'
```
